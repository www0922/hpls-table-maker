# HPLS 文库表自动化生成方案 PDF 设计说明

## 1. 文档目标

- 产物：面向领导汇报的横向 A4 PDF 方案文档。
- 核心任务：用业务语言说明项目解决了什么问题、如何实现、人机如何分工、取得了什么成效，以及如何复用。
- 阅读目标：领导在 5 分钟内理解项目价值、可信边界和复制方法。
- 页数：7 页，不设置单独的“推广建议”页。

## 2. 事实依据

文档内容以现有项目实现与已确认实测数据为依据：

| 依据 | 用途 |
| --- | --- |
| `README.md`、`操作手册.md` | 四类表型、输入文件、自然语言操作与输出契约 |
| `.workbuddy/skills/hpls-table-maker/SKILL.md` | AI 入口、表型路由、保护规则与交付条件 |
| `.workbuddy/skills/hpls-table-maker/scripts/run_table.py` | 前置检查、覆盖保护、子流程调度和输出存在性检查 |
| 四类 `code/run_all.py` | PE100、PE150、XP、真迈的实际流水线结构 |
| 四类 `validate_output.py` 与 `common/validate_utils.py` | 关键业务规则校验与失败中止机制 |
| `PPT大纲.md` 及用户确认 | 手工 1-2 小时、自动化 1-2 分钟、流水线性能提升 60%+ 均为实测数据 |

## 3. 内容结构

### 第 1 页：封面

- 标题：HPLS 文库表自动化生成方案。
- 核心表达：从手工做表 2 小时到一句话生成 1 分钟。
- 辅助信息：成果汇报、日期、覆盖 PE100 / PE150 / XP / 真迈。

### 第 2 页：成果摘要

- 用四个结论卡片前置业务价值：处理时长下降约 98%、单批释放约 88.5 分钟、覆盖 4 类表型、1 个自然语言入口。
- 强调三个可信机制：规则固化、输入预检、输出校验。
- 明确价值不是“替代专业人员”，而是将专业人员从重复制表转向异常判断与质量复核。

### 第 3 页：业务痛点

- 多源数据：PE100 / PE150 每批涉及 3 类源表，XP / 真迈涉及 5 类源表。
- 多规则链：数据迁移、匹配、分组、公式、命名、稀释、qPCR 等步骤相互依赖。
- 强人工依赖：大量复制粘贴和公式维护，经验难以标准化传承。
- 风险表现：单批 1-2 小时，错漏难追溯，新人培训周期长，跨平台规则维护成本高。

### 第 4 页：方案设计

- 用五层闭环呈现数据流：源数据准备 -> AI 统一入口 -> 前置检查 -> 规则流水线 -> 校验与交付。
- 呈现四类管线差异：PE100 6 个核心步骤，PE150 7 个，XP / 真迈各 9 个核心步骤并生成 qPCR 定量表。
- 呈现三道防线：输入契约、失败即中止、输出规则校验。
- 保护边界：不修改原始模板，不删除或重命名源表，不在多个候选文件间静默选择。

### 第 5 页：人机分工

- 执行前：人确认表型、批次与源表；机器识别意图并执行预检。
- 执行中：机器完成确定性、重复性操作；输入歧义、规则冲突或来源警告返回给人处理。
- 执行后：机器执行校验并交付输出；人负责关键结果复核和最终质量放行。
- 分工原则：人定边界，机器执行，异常回到人。

### 第 6 页：量化成效

- 实测区间：手工 60-120 分钟，自动化 1-2 分钟。
- 中位数推导：手工 90 分钟，自动化 1.5 分钟。
- 处理时长下降：`(90 - 1.5) / 90 = 98.33%`，对外表述为“约 98%”。
- 单批释放时间：`90 - 1.5 = 88.5` 分钟。
- 流水线性能提升 60%+ 单独用于说明减少重复 Excel I/O 后的程序性能优化，不与端到端处理时长下降混为同一指标。
- 不外推年度节省工时，因为文档没有经确认的年度批次数。
- 不宣称零错误；表述为“关键业务规则自动校验，显著降低人工错漏风险”。

### 第 7 页：复用方案

- 五类标准资产：输入契约、输出模板、规则模块、校验清单、AI 入口。
- 直接复用的通用骨架：文件发现、覆盖保护、步骤编排、错误翻译、日志输出、结果存在性检查和交付机制。
- 按新平台适配的业务差异：源表字段、匹配规则、分组逻辑、公式、模板、命名与业务阈值。
- 复制路径：盘点人工步骤 -> 固化输入输出契约 -> 模块化规则 -> 建立校验 -> 接入 AI 入口。

## 4. 视觉设计

- 方向：经营成果看板式，先结论、后机制、再复用。
- 版式：横向 A4，7 页；每页保持一个核心结论和一个主视觉关系。
- 主色：炭黑 `#17202A`、白色、青绿 `#16A085`。
- 强调色：橙红 `#E05D3F`、暖黄 `#F2A65A`；用于数字、风险和关键标签。
- 背景色：浅灰 `#F4F6F7`、浅绿 `#EDF7F4`、浅橙 `#FFF4EB`。
- 字体：优先使用系统可嵌入的中文黑体；数字与英文使用同一无衬线体系，避免字体风格混杂。
- 页眉：章节英文标签与中文标题；页脚：项目简称、日期、页码。
- 图表：使用扁平柱形图、流程节点和矩阵，不使用装饰性渐变、复杂插画或无数据支撑的图形。

## 5. 信息边界

- 不包含单独的推广建议或未来展望页。
- 不写未经确认的年度 ROI、错误率、批次规模或人员成本。
- 不暴露源数据内容、样本编号或其他敏感业务数据。
- 技术细节仅用于证明可靠性，不展开脚本级实现说明。

## 6. 生成与质量校验

- 使用 ReportLab 生成最终 PDF，输出到 `output/pdf/HPLS文库表自动化生成方案_领导汇报版.pdf`。
- 首次生成前按 PDF 技能要求记录一次创建型 artifact operation。
- 生成后用 `pdfinfo` 检查页数与页面尺寸，用 `pdftoppm` 将全部页面渲染为 PNG。
- 逐页检查中文字体、标题层级、图表比例、边距、页码、文本换行、颜色对比和内容溢出。
- 使用 PDF 文本提取检查 7 个章节标题和关键数字是否存在。
- 只有在全部 7 页无裁切、重叠、乱码和黑块后才交付。

## 7. 已确认决策

- 使用场景：给领导做成果汇报。
- 内容路线：成果汇报型。
- 页面数量：7 页，删除原第 8 页推广建议。
- 视觉方向：A 经营成果看板式。
- 方案设计、人机分工、量化成效和复用方案页面草图均已确认。
- 量化数据为实测确认，衍生指标按本说明中的中位数公式计算。
