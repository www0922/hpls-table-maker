## 涉及文件

| 文件 | 代号 | 说明 |
|------|:--:|------|
| `江西华大T7+上机-PE100-*.xlsx` | A表 | 上机数据源，含多个 sheet |
| `PE100_pooling模板表.xlsx` | B表模板 | 输出模板（根目录，只读） |
| `YYYYMMDD文库pooling表T7+PE100.xlsx` | B表输出 | 最终结果（output_result/） |
| `外包文库质检总表*.xlsx` | C表 | 外包文库质检数据 |
| `*自建库*.xlsx` | D表 | 自建库出库数据 |

**自动发现：** 脚本按关键词搜索 `input_data/` — A表含"上机"、C表含"质检"、D表含"自建库"。自动排除 Excel 临时文件（`~$` 开头）。

**输出命名：** 格式为 `YYYYMMDD文库pooling表T7+PE100.xlsx`，日期取自当天（如 `20260806文库pooling表T7+PE100.xlsx`）。

**工作流程：** `clear_pooling.py` 先将模板复制到 `output_result/`，所有后续步骤操作该副本，原始模板不被修改。

## 代码架构

各步骤脚本通过 `config.py` 获取路径和工具函数。`config.py` 底层调用 `common/` 公共模块：

| 模块 | 功能 |
|------|------|
| `common/file_utils.py` | `find_file()` 文件搜索、`prepare_output()` 模板复制 |
| `common/sheet_utils.py` | `sheet_map_a()` Sheet 映射、`sync_b_table_sheets()` Sheet 同步、`is_data_sheet()` 判断数据 sheet |
| `common/format_utils.py` | `apply_standard_format()` 统一字体/行高/数字格式/列宽 |
| `common/step_runner.py` | `run_pipeline()` 顺序执行步骤、进度打印、错误翻译 |
| `common/validate_utils.py` | `validate_data_sheet()` / `check_sheet_order()` / `check_t7_sheet()` 输出校验 |

## 执行顺序

```
clear_pooling.py → step1_migrate.py → step2_lookup.py → step3_group_sort.py
→ step4_naming.py → step5_t7_prepare.py → format_font.py → step6_down_data.py → validate_output.py
```

| 步骤 | 脚本 | 功能 |
|:--:|------|------|
| 0 | `clear_pooling.py` | 复制模板、动态同步 sheet、清空数据 |
| 1 | `step1_migrate.py` | A表 → B表 数据迁移 |
| 2 | `step2_lookup.py` | C表/D表 → B表 查找填充 |
| 3 | `step3_group_sort.py` | 分组、公式计算、汇总 |
| 4 | `step4_naming.py` | Lane编号、合并、框线 |
| 5 | `step5_t7_prepare.py` | T7+制备 数据填充与公式 |
| 6 | `format_font.py` | 字体、行高、数字格式、Sheet排序 |
| 7 | `step6_down_data.py` | 下机数据统计模版 填充 |
| 8 | `validate_output.py` | 输出校验 |

> step6 必须在 format_font 之后运行，因为下机表 D 列使用整数格式，需覆盖 format_font 的全局 D 列 `0.00` 格式。

## config.py 核心函数

| 函数 | 功能 |
|------|------|
| `find_file(keyword)` | 委托 `common/file_utils.find_file()` |
| `get_src_a()` / `get_src_c()` / `get_src_d()` | 获取 A/C/D 表路径 |
| `prepare_output()` | 复制模板到 output_result（已存在则跳过） |
| `reset_output()` | 强制重新复制模板 |
| `sheet_map_a()` | 委托 `common/sheet_utils.sheet_map_a()`，优先级 `('letter', 'number')` |
| `get_target_sheets()` | 动态获取 B表目标数据 sheet 列表 |
| `is_data_sheet(name)` | 委托 `common/sheet_utils.is_data_sheet()` |
| `sync_b_table_sheets(wb)` | 委托 `common/sheet_utils.sync_b_table_sheets()` |

### Sheet 映射规则

PE100 按优先级依次匹配（`letter` 优先）：

1. **直接字母匹配**：A表 sheet 名是单个大写字母（如 `C`、`D`）→ 直接使用
2. **数字映射**：`1→A, 2→B, 3→C, 4→D, 5→E...`

> 上机表 sheet "3"、"4" → pooling 表 C面、D面。

### 动态 Sheet 同步

根据 A表映射结果自动调整 B表的数据 sheet：
- **重命名优先**：将模板中多余的 sheet 重命名为缺失的 sheet（如 A→C）
- **删除多余**：A表无对应数据的 sheet 直接删除
- **复制创建**：重命名不够时，从现有数据 sheet 复制创建
- **非数据 sheet**（如 T7+制备、下机数据统计模版、B1-B3）保留不动

## 步骤零：清空模板

**脚本：** `clear_pooling.py`

1. 复制 `PE100_pooling模板表.xlsx` → `output_result/YYYYMMDD文库pooling表T7+PE100.xlsx`（已有则跳过）
2. **同步 B表 sheet**：调用 `sync_b_table_sheets()`
3. 清空所有工作表：
   - 解除第 2 行起的全部合并单元格
   - 删除第 2 行起的所有数据行
   - 表头行（第 1 行）保留不动

## 步骤一：数据迁移（A表 → B表）

**脚本：** `step1_migrate.py`

**操作对象：** B表的数据工作表（由 `get_target_sheets()` 动态确定）

**读取方式：** A表使用 `data_only=True` 模式读取，获取公式的缓存计算结果而非公式文本。

**列映射：**

| # | A表 | → | B表 | 说明 |
|---|------|---|------|------|
| 1 | B列/C列合并格(池文库编号) | → | B列(文库编号) | 最优先 |
| 2 | C列(HaploX编号) | → | B列 | 次优先 |
| 3 | C列为空 → D列(样本名称) | → | B列 | 最终回退 |
| 4 | J列(预分配数据量M) **× 0.13** | → | D列(数据量G) | M→G 换算 |
| 5 | 池文库合并范围 J列求和 × 0.13 | → | D列 | 池文库汇总 |
| 6 | H列(文库类型) | → | G列(文库类型) | |
| 7 | L列(客户单位) | → | H列(客户单位) | |
| 8 | M列(备注) | → | K列(备注) | |

**去重：** B列相同文库编号保留首行。空文库编号的行跳过。

## 步骤二：查找填充（C表/D表 → B表）

**脚本：** `step2_lookup.py`

**操作对象：** B表的数据工作表（动态确定）

**匹配逻辑：**

| 文库编号格式 | 查询表 | 匹配列 | 举例 |
|------------|:--:|------|------|
| `HGC-Lib-数字` | C表 | F列(HGC编号) | HGC-Lib-26079733 |
| `HGC-POOL-数字` | C表 | F列(HGC编号) | HGC-POOL-26079890 |
| 其他 | D表 | Col3(杂交编号) 优先，Col4(样本编号) 兜底 | HGC-25160018, 250983E |

> C表、D表均通过**表头文本子串匹配**自动定位列位置，不硬编码列号。C表搜索所有 sheet，D表搜索第一个 sheet。

**C表匹配填充：**

| C表列 | → | B表列 | 说明 |
|--------|---|------|------|
| L列(Qubit浓度) | → | C列 + M列 | M列与C列相同值 |
| M列(平均片段) | → | N列(片段) | |
| Z列(人工检测结果) | → | O列(人工检测) | |
| AA列(人工备注) | → | P列(人工备注) | |

**D表匹配填充：**

| D表列 | → | B表列 | 说明 |
|--------|---|------|------|
| K列(Qubit浓度) | → | C列 + M列 | |
| N列(平均片段) | → | N列(片段) | |

## 步骤三：分组、公式计算、汇总

**脚本：** `step3_group_sort.py`

**操作对象：** B表的数据工作表（动态确定）

### 文库类型判定

全库只有 **CDNA** 和 **Oligo** 两类。优先看 **N列（片段）**，N列为空则回退到 **G列（文库类型）**：

| 优先级 | 条件 | 结果 |
|:--:|------|:--:|
| 1 | N列 ≥ 300 | cdna |
| 2 | 100 ≤ N列 < 300 | oligo |
| 3 | N列 < 100 | cdna |
| 4 | N列无数据 + G列含 oligo/Oligo | oligo |
| 5 | N列无数据 + G列不含 oligo | cdna（默认） |

### 客户单位归一化

| 归一化 key | 包含 |
|------|------|
| `广州基迪奥/奥智` | 广州基迪奥科技服务有限公司、广州奥智生物科技有限公司 |

归一化仅用于分组 key，写入单元格仍是原始名称。

---

### CDNA 分组

**全部 CDNA 统一类型**，不分子类型。按以下优先级预分组：

| 优先级 | 条件 | key | 说明 |
|:--:|------|------|------|
| ① | D列(数据量) ≤ 10G | `_cross_customer_` | 跨客户合并 |
| ② | C列(Qubit浓度) ≤ 15 | `(归一化客户, C_low)` | 按客户分层 |
| ③ | 其余（C>15 且 D>10） | `归一化客户` | 按客户分组 |

**组内约束：**

| 约束 | 值 |
|------|:--:|
| 最多样本 | 10 |
| 数据量总和 | ≤ 600G |
| F ratio（最大/最小） | ≤ 5x |
| 投入量 | 450ng（F>8ul → 300ng） |
| 不满足条件 | 单样本成组 |

---

### Oligo 分组

**全部 Oligo 统一**，不分子类型，不区分客户。

| 约束 | 值 |
|------|:--:|
| 最多样本 | 12 |
| F ratio（最大/最小） | ≤ 5x |
| 投入量 | 450ng（F>8ul → 300ng） |
| 数据量 | 不限 |
| 不满足条件 | 单样本成组 |

按 D/C 比值排序后贪婪分组以控制 F ratio。

---

### 通用规则

- **F ratio 计算**：`max(D/C) / min(D/C) ≤ 5`（与 D_sum 和投入量无关）
- **排列顺序**：CDNA 组在前 → Oligo 组在后
- **组内排序**：按文库编号（B列）升序
- **组间无空行**：每组数据行后紧跟汇总行

### 公式

| 列 | 公式 | 说明 |
|----|------|------|
| E列(文库摩尔质量) | `=D/D{汇总行}*{投入量}` | Excel公式，投入量 450 或 300 |
| F列(最终取样体积) | `=ROUND(E/C,3)` | Excel公式 |

### 汇总行

| 列 | 内容 | 说明 |
|----|------|------|
| B | 本组数据条数 | 如 8 条写入 `8` |
| D | 组数据量合计 | 静态值 |
| E | `=ROUND(SUM(E范围),3)` | Excel公式 |
| F | `=ROUND(SUM(F范围),3)` | Excel公式 |
| I | `=ROUND(40-F汇总,3)` | TE Buffer，湖蓝色底色 |

## 步骤四：Lane编号、合并、框线

**脚本：** `step4_naming.py`

**操作对象：** B表的数据工作表

**分组识别：** 通过汇总行识别（B列为数字条数 + D列有值）。

### Lane 命名

格式：`{sheet名}{序号}`，如 C1, C2... 或 D1, D2...

### 合并与框线

- 组内样本数 > 1 时，A列合并单元格；单样本组不合并
- 数据行 **A~H列** 加框线
- 汇总行不加框线

---

## 步骤五：T7+制备

**脚本：** `step5_t7_prepare.py`

**操作对象：** B表 T7+制备 工作表

**分组识别：** 通过汇总行 B列为数字条数识别。

### 数据来源

从数据 sheet 各组汇总行读取：

| Pooling表 | → | T7+制备 | 说明 |
|-----------|------|------|------|
| A列(Lane编号) | → | B列(文库ssDNA编号) | |
| D列(汇总数据量) | → | H列(数据量) | |
| E列(组摩尔质量合计) | → | S列(环化投入量) | 解析E列公式末尾的投入量数值 |
| G列(文库类型) | → | N列(文库类型) | |
| H列(客户单位) | → | O列(客户单位) | |

### laneID

格式：`MMDD + 面号`，如 `0806C`。同一面号为一组，面间空一行分隔。

### 自动公式

| 列 | 公式 | 说明 |
|----|------|------|
| E | D与中位值比较 | ≤100→"正常"，超→"偏大Xbp"/"偏小Xbp" |
| F | `=D×0.33×G×0.001` | |
| G | `=900×L` | |
| I | `=ROUND(H/H总,4)` | |
| K | `=I×J` | |
| L | `=K/K总` | |
| M | `=F/C` | |
| Q | `=I×J` | |
| R | `=22×C/S` | 转换效率 |
| S | 组E列合计 | 环化投入量（静态数值） |

### 用户填入

| 列 | 说明 |
|----|------|
| C | SSDNA浓度 |
| D | 平均片段(bp) |
| J | 调整比例 |

### 汇总行（每面末行）

| 列 | 公式 |
|----|------|
| D | `=MEDIAN(D范围)` |
| H | `=SUM(H范围)` |
| K | `=SUM(K范围)` |
| M | `=SUM(M范围)` |
| P | `=96-M汇总`（湖蓝色底色） |

仅数据行加框线（A~Q列），汇总行不加。

## 步骤六：下机数据统计模版

**脚本：** `step6_down_data.py`

**操作对象：** B表 下机数据统计模版 工作表

从 T7+制备 逐行读取，每条 T7 行对应下机表一行（不聚合）。文库条数从数据 sheet 汇总行 B列按 lane名匹配。

### 列结构（A-N）

| 列 | 内容 | 来源/公式 | 格式 |
|:--:|------|------|:--:|
| A | FlowCell_ID | 留空（人工填写） | 全表合并 |
| B | Lane_Number | T7 A列 取末尾字母 | 按Lane合并 |
| C | 该lane产量(M) | 留空（QC CSV填写） | |
| D | 文库数量 | 数据 sheet 汇总行 B列 | 整数 |
| E | 文库类型 | T7 N列 | |
| F | 客户单位 | T7 O列 | |
| G | 客户需求数据量(G) | T7 H列 | `0.00` |
| H | 实际数据量 | 留空（QC CSV填写） | `0.00` |
| I | 欠缺数据量(G) | `=H-G` | `0.00` |
| J | 补充数据比例 | `=I/G` | `0.00%` |
| K | 上机模式 | "T7+100" | 全表合并 |
| M | 操作人员 | 留空 | |
| N | 异常原因 | 留空 | |

### 条件格式

- I列 < 0 → 浅红色填充
- J列 < 0 → 浅红色填充

### 框线

数据行 A~N列全部加框线。
